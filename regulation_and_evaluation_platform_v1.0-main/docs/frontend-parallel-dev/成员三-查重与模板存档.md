# 成员三：查重服务与模板与存档开发约定

本文约定**成员三**在并行开发中的职责边界、代码与资源放置位置，以及 Git 合并与自测要求。全组通用规则见同目录 [README.md](./README.md)。

---

## 1. 负责范围与路由

| 模块 | 路由 path | 页面入口 |
|------|-----------|----------|
| 查重服务 | `/duplicate-check` | `frontend/src/pages/duplicate-check/index.tsx` |
| 模板与存档 | `/template-archive` | `frontend/src/pages/template-archive/index.tsx` |

**职责概要**：

- **查重服务**：拟建标准名称/关键词/大纲输入、相似度阈值设置、结果列表与查重报告入口（与需求文档「查重服务模块」一致）。
- **模板与存档**：模板配置、历史记录查询、下载中心（上传模板、检索报告、预览与批量下载等前端能力）。

两人格模块由**同一人**维护，便于统一「报告类」交互与文件上传体验。

---

## 2. 代码目录与文件命名

两个模块**分别**使用独立目录，禁止混写在对方根目录下：

### 查重服务 `pages/duplicate-check/`

| 类型 | 放置位置 |
|------|----------|
| 入口 | `pages/duplicate-check/index.tsx` |
| 组件 | `pages/duplicate-check/components/` |
| hooks / utils | `pages/duplicate-check/hooks/`、`utils/` |
| 静态资源 | `pages/duplicate-check/assets/` |
| 接口 | `frontend/src/services/duplicate-check.ts` |
| 状态 | `frontend/src/stores/duplicate-check.ts`（若需要） |
| 类型 | `frontend/src/types/duplicate-check.ts` |

### 模板与存档 `pages/template-archive/`

| 类型 | 放置位置 |
|------|----------|
| 入口 | `pages/template-archive/index.tsx` |
| 组件 | `pages/template-archive/components/` |
| hooks / utils | `pages/template-archive/hooks/`、`utils/` |
| 静态资源 | `pages/template-archive/assets/` |
| 接口 | `frontend/src/services/template-archive.ts` |
| 状态 | `frontend/src/stores/template-archive.ts` |
| 类型 | `frontend/src/types/template-archive.ts` |

### 两模块共用组件时的规则

- 若组件**仅**被查重与模板两个模块使用：优先放在 **`frontend/src/components/`** 下独立文件夹（如 `components/ReportDownload/`），在 PR 中说明「查重 + 模板存档共用」。
- 若未来三个以上模块共用，再考虑上收命名与文档更新。

---

## 3. Ant Design / ProComponents 使用边界

- 查重结果列表、历史记录列表优先 **ProTable**（筛选、分页、工具栏与项目习惯一致）。
- 上传模板、企标类文件使用 **Upload**，注意 `beforeUpload`、大小限制与错误提示与后端约定一致。
- 下载中心注意批量操作时的 loading 与部分失败提示，避免重复点击。

---

## 4. 接口与 Mock

- `services/duplicate-check.ts` 与 `services/template-archive.ts` 分离，**不要**合并成单文件，以免接口膨胀后难以 code review。
- 文件下载若走「先拿 URL 再打开」或 blob，将逻辑封在对应 service 或 `utils/download.ts`（若建共享工具，放在 `frontend/src/utils/` 并在 PR 说明）。

---

## 5. Git 分支、PR 与 Code Review

- **个人分支**：在 GitHub 上以主分支为基线创建**自己的功能分支**，查重与模板存档相关修改**全部在该分支上**完成后再发 PR 合入主分支；勿直接在主分支上开发。完整流程见 [README.md - GitHub 分支与合并流程](./README.md#github-分支与合并流程)。
- **分支命名**：`feature/dupcheck-<简述>` 或 `feature/template-archive-<简述>`；若同一 PR 同时改两个模块，命名可写 `feature/dupcheck-template-<简述>`，并在描述中列出两模块变更点。
- **共享文件**：仍遵循只改与本模块相关的路由行；`routes/index.tsx` 中两个 `path` 可能相邻，合并时注意冲突。

---

## 6. 自测清单

- [ ] `npm run build` 通过。
- [ ] `/duplicate-check` 与 `/template-archive` 均可访问。
- [ ] 上传/下载相关改动在浏览器内手动试一遍基础流程（含失败提示）。
- [ ] 新增依赖已说明。

---

## 7. 与其他成员的协作点

- **合规性评价**（成员二）：若报告编号、下载格式与合规报告同源，约定统一类型字段或跳转参数。
- **系统审计**（成员五）：历史操作记录若需跳转到「某次下载/某条任务」，路径与 query 参数事先对齐。
