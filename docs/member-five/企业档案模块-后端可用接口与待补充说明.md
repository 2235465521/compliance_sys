# 企业档案模块：后端可用接口与待补充说明

本文档与《[后端接口说明文档.md](../../后端接口说明文档.md)》、[03-enterprise-archive.md](./03-enterprise-archive.md) 及《[后端未实现的接口信息汇总.md](./后端未实现的接口信息汇总.md)》**§3** 配合使用。全局约定以根目录《后端接口说明文档》**§1** 为准。

## 1. 结论摘要

| 类别 | 说明 |
|------|------|
| **能支撑企业主档/一企一库列表的 HTTP** | 现行说明文档**未提供**企业实体 CRUD 或主从树接口；**无可直接联调的主功能路径**。 |
| **弱相关（易混淆）** | 若干接口字段名带「企业」或列表名含 `affected_enterprise*」，语义为**企标号**或标准维度，**不得**当企业主键/社会信用代码使用（见 **§2**）。 |
| **本模块当前前端实现** | 任务列表/详情/新建/编辑/删除/关联表展示**均为 Mock**（`services/enterprise-archive.ts` + 内存 store）；对接后端后应替换。 |

## 2. 弱相关接口（不替代企档主数据）

| 方法 | 路径 | 文档/语义要点 | 为何不能当「企业库」用 |
|------|------|---------------|------------------------|
| POST | `/api/mapping/save/` | `enterprise_bz_id` 为**企标在库中的 bz 标识/标准号维度** | 主数据是**标准映射**非工商主档。 |
| GET | `/api/standards/warning-trace/` | 返回中 `affected_enterprises` 在示例里为**企标号**列表 | 与「一企一库」企业 ID/信用代码模型不一致。 |
| POST | `/api/insert_anti_warn/` 等 | 以企标/引用为锚点 | 非企业主档管理。 |

## 3. 待补充接口（建议契约，示例级）

与「一企一库」产品一致时，可向后端落类似下述契约（**路径与字段以评审为准**；此处仅供缺口对齐与联调前讨论）。

### 3.1 企业主档

- `GET /api/enterprises/`：分页、筛选（名称、社会信用代码、状态等）  
- `POST /api/enterprises/`：创建主档。  
- `GET /api/enterprises/{id}/`：详情。  
- `PATCH /api/enterprises/{id}/` / `PUT`：更新主档。  
- `DELETE /api/enterprises/{id}/`：删除（与权限/软删策略一致）  

**用途**：与前端列表/新建/详情/编辑/删除一一对应；**替代**目前 Mock 层。

### 3.2 与「关联专用表」子资源

- `GET /api/enterprises/{id}/reference-sheets/`（或同义命名）：该企业下企标查新**专用表**行或任务摘要列表。  

**用途**：支撑详情页「关联专用表」独立加载与失败不拖垮主档；可与查新/任务服务关联 ID。

### 3.3 权限

- 创建/编辑/删除/敏感字段可见性**以后端 403/角色为准**；前端在接口未就绪前仅有按钮占位说明。
