# 系统安全模块：后端可用接口与待补充说明

本文档与《[后端接口说明文档.md](../../后端接口说明文档.md)》、[04-system-security-audit.md](./04-system-security-audit.md) 及《[后端未实现的接口信息汇总.md](./后端未实现的接口信息汇总.md)》**§4** 配合使用。全局约定以根目录《后端接口说明文档》**§1** 为准。

## 1. 结论摘要

| 类别 | 说明 |
|------|------|
| **能支撑 SPA「用户 / 角色 / 系统审计」主链的 HTTP** | 现行说明文档以 **Django Admin Session** 为主；**未列出**面向 SPA 的用户管理、RBAC 角色绑定、**全流程系统审计日志**（列表 + 详情含 **Diff**）等 JSON REST。**当前无可直接联调的主功能路径**。 |
| **易混淆：业务「审核台」≠ 系统「审计」** | `/api/audit/pending_indexes/`、`/api/audit/submit/`、`/api/audit/bulk_submit/` 等为 **Dify/技术指标审核流程**，**不得**作为 `/system/audit-log` 产品需求中的「登录、标准库修改、专用表 Diff、导出」等**系统级审计**数据源（与 [04-system-security-audit.md §8.2](./04-system-security-audit.md) 一致）。 |
| **本模块当前前端实现** | `services/system.ts` + `stores/system.ts` 为 **Mock**；顶栏「演示视角」用于验证超管与操作员在审计入口上的差异；对接后端后应整文件替换为真实请求层。 |

## 2. 易混淆接口（业务审核，不可替代系统审计）

| 方法 | 路径 | 文档语义 | 为何不能当「系统审计」用 |
|------|------|----------|--------------------------|
| GET | `/api/audit/pending_indexes/` | 待审核**技术指标**列表 | 领域为**指标审核台**，非操作审计日志。 |
| POST | `/api/audit/submit/` | 单条通过/打回 | 同上。 |
| POST | `/api/audit/bulk_submit/` | 批量审核 | 同上。 |

前端路由、菜单、文档命名建议区分 **「审核台」** 与 **「安全审计」**，避免与 `/system/audit-log` 混为一谈。

## 3. 待补充接口（建议契约，示例级）

以下仅供缺口对齐与联调前讨论；**路径、字段、分页参数以评审为准**。

### 3.1 用户管理

- `GET /api/system/users/`：分页、筛选（用户名、状态、角色等）。  
- `POST /api/system/users/`：创建用户。  
- `GET /api/system/users/{id}/`：详情。  
- `PATCH /api/system/users/{id}/`：更新（显示名、邮箱、角色、启用等）。  
- `DELETE /api/system/users/{id}/`：删除（与软删/保护策略一致）。  
- （可选）`POST /api/system/users/{id}/reset-password/`：重置密码。

### 3.2 角色与权限

- `GET /api/system/roles/`：角色列表。  
- `POST /api/system/roles/`：创建角色。  
- `GET /api/system/roles/{id}/`：详情（含权限 key 列表）。  
- `PATCH /api/system/roles/{id}/`：更新名称、权限绑定。  
- `DELETE /api/system/roles/{id}/`：删除。  
- `GET /api/system/permissions/`（或嵌在 `roles` 响应中）：**权限树**扁平或树形结构，与前端 `Tree` 勾选一致。

### 3.3 系统审计日志

- `GET /api/system/audit-logs/`：分页、筛选（时间范围、操作人、模块、操作类型、关键字、结果状态等）。  
- `GET /api/system/audit-logs/{id}/`：单条详情，载荷需包含 **字段级** `before`/`after` 或 `changes[]`，以支撑 **Diff** 组件渲染。  
- `POST /api/system/audit-logs/export/`（或异步任务模式）：导出任务创建；`GET /api/system/export-jobs/{id}/` 轮询状态与下载 URL（若采用异步导出）。

**语义**：只追加、不可篡改等策略若影响前端（例如禁止删除），应以错误码与说明文档形式固定。

### 3.4 鉴权

- SPA 与 Admin 的 **Session/JWT** 边界、**仅超级管理员**可访问审计列表/导出等规则，需与说明文档 **§1** 及安全设计一致；前端在接口未就绪前仅用 Mock 演示路由与 Tab 显隐。
