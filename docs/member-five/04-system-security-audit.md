# 系统安全与审计模块：界面规划说明

本文档依据「安全与审计」业务流程图（7.1 角色权限校验、7.2 审计范围与静默记录、加密存储、超管查询与 Diff）与《标准化信息服务平台——需求分析文档》第 8.7 节、第 10.3～10.4 节整理。前端实现 **RBAC 管理界面** 与 **审计日志查询 + Diff 展示**；日志的采集、加密、只追加存储为**后端职责**，文档仅作交互与权限说明。**后端 HTTP 对照见第 8 节**，《[后端接口说明文档.md](../../后端接口说明文档.md)》当前以 **Django Admin Session** 为主，**未见**独立用户/角色/审计日志 JSON API。

---

## 1. 模块目标与范围

### 1.1 目标

- **7.1**：提供用户、角色（及权限绑定）的管理界面，体现「超级管理员」与「操作兼审核员」的能力差异（具体权限项以后端模型为准）。
- **7.2**：超级管理员可检索、查看全流程审计记录，并在详情中查看 **修改前 vs 修改后** 的 **Diff**，支持导出（若业务开放，须二次确认与权限控制）。

### 1.2 本期不包含

- 登录页、全局会话实现（可能在 `main` 或独立认证模块）。
- 审计日志的存储引擎与加密实现。
- 与其他业务模块内嵌审计入口（本模块集中查询为主）。

---

## 2. 业务流程对齐

| 流程图节点 | 含义 | 界面落点 |
|------------|------|----------|
| UserAction | 用户发起操作 | 全站各模块（非本页专属） |
| AuthCheck | 7.1 角色权限校验 | 路由守卫、菜单过滤、按钮显隐；请求 403 统一提示 |
| FullAccess | 超管全权限 | 可见 `users` / `roles` / `audit-log` |
| BizAccess | 操作员仅业务流 | 不可见审计菜单；不可访问审计路由 |
| Deny | 拒绝并记录异常 | 无权限时 **403** 页面或提示（不暴露审计入口） |
| ActionCapture / AuditScope | 后台捕捉与范围 | 无独立 UI；审计列表按类型筛选即可 |
| LogGen / LogStore | 生成条目、入库 | 后端；列表与详情展示结果 |
| TimeStamp | 人、秒、IP | 列表列、详情元数据区 |
| AuditView | 超管调取审计 | `/system/audit-log` |
| DiffView | Diff 视图 | 审计详情 **Drawer** 或独立页 |
| End | 完成责任溯源 | — |

**审计范围（流程图子图）与前端筛选维度对应建议**：

| 范围类型 | 筛选或列展示 |
|----------|----------------|
| 登录/退出 | 操作类型 = 认证类 |
| 标准库录入/修改 | 模块 = 标准库；详情走 Diff |
| 专用表修改 | 模块 = 合规/查新等（以后端分类为准）；**必须 Diff** |
| 评价/预警审核意见 | 操作类型 = 审核 |
| 报告下载/导出 | 操作类型 = 导出/下载 |

## 3. 信息架构与路由

### 3.1 建议路由（前缀 `/system`）

| Path | 说明 |
|------|------|
| `/system` | 模块入口：卡片导航，或 **重定向** 至 `/system/users` |
| `/system/users` | 用户管理 |
| `/system/roles` | 角色与权限 |
| `/system/audit-log` | 审计日志（**仅超级管理员**菜单与路由） |

实现时在 [`frontend/src/routes/index.tsx`](../../frontend/src/routes/index.tsx) 中为 `system` 增加 `children`；侧栏在「系统安全与审计」下挂二级菜单，或模块首页自导航。

### 3.2 与流程图一致的产品要求

- 操作兼审核员在前端 **不得** 通过菜单或已知 URL 探测到审计后台；超管专属路由在无权限时 **Navigate 到 403 或首页**（与后端一致）。

## 4. 界面清单（按页面）

### 4.1 模块首页 `/system`（可选）

- **功能**：三张卡片入口：用户管理、角色权限、审计日志（审计卡片对非超管隐藏）。
- **空态**：可不建首页，直接重定向到 `users`。

### 4.2 用户管理 `/system/users`

- **功能**：用户列表；新建/编辑；启用/禁用；重置密码（若开放）；分配角色。
- **布局**：`ProTable` + **Drawer** 表单。
- **操作**：删除用户 **Modal.confirm**；禁用二次确认。
- **空态**：引导创建用户。

### 4.3 角色管理 `/system/roles`

- **功能**：角色列表；新建/编辑角色；为角色勾选权限（树或分组 Checkbox）。
- **布局**：**左角色列表 + 右权限配置** 或 **表格 + 大 Drawer 内权限树**。
- **校验**：至少一名超管角色存在等业务规则由后端返回，前端展示错误信息。

### 4.4 审计日志 `/system/audit-log`

- **功能**：多条件筛选（时间范围、操作人、模块、操作类型、关键字）；分页列表；查看详情；导出（超管、二次确认）。
- **列表列**：时间、操作人、IP、模块、操作摘要、结果状态等（以后端为准）。
- **详情**：元数据 + **Diff 区**：字段级「旧值 | 新值」或左右分栏对比，**高亮**差异；禁止仅展示「某某修改了数据」而无内容对比（与需求 10.3 一致）。
- **导出**：`Modal.confirm`；成功后下载或异步任务提示。
- **空态**：无记录时说明调整筛选条件。

## 5. 布局与组件级建议

| 场景 | 建议 |
|------|------|
| 用户表单 | `ProForm` + 角色 `Select` 多选 |
| 权限树 | `Tree` 带 Checkbox；数据量大时懒加载 |
| Diff | 结构化数据：按字段行展示；长文本用折叠或 `diff` 样式块；可复用内部小组件 `AuditDiffViewer`（放 `src/components`） |
| 审计表 | `ProTable` + 服务端分页；列宽可配置（可选） |

---

## 6. 权限与可见性

- **审计菜单与路由**：仅超级管理员；路由级与菜单级双重控制。
- **敏感操作**：删除用户、批量导出审计、修改超管权限等必须使用 **`Modal.confirm`**，错误提示与后端错误码对齐（见成员五开发约定）。
- **操作员**：仅能访问业务模块；访问 `/system/audit-log` 时统一拒绝。

---

## 7. 非功能与体验

- 审计列表可能数据量大，必须 **后端分页**；导出异步时轮询或通知。
- Diff 加载失败时单独错误提示，不白屏。
- 时间显示建议带时区或统一用服务器时间说明（产品定）。

## 8. 后端接口对照（摘自《后端接口说明文档》）

### 8.1 管理端与鉴权（文档原文）

| 约定 | 说明 |
|------|------|
| 业务接口前缀 | `/api/` |
| 管理后台 | `/admin/`，**Admin 需登录 Session**（非文档中多数 `AllowAny` 的 `/api/` 风格） |
| 用户 / 角色 / 系统级审计日志 | **未在《后端接口说明文档》HTTP 章节列出** REST 路径；若前端要实现 `/system/users`、`/roles`、`/audit-log`，需后端提供 **JWT/Session + CRUD** 或约定复用 Django Admin 的只读 API |

### 8.2 名称易混淆：业务「审核」≠ 系统「审计日志」

下列接口属于 **Dify/指标审核台**（合规业务流程），**不是**流程图 7.2 中的「全流程操作审计日志」查询接口。

| 方法 | 路径 | 实际用途 |
|------|------|----------|
| GET | `/api/audit/pending_indexes/` | 待审核**技术指标**列表 |
| POST | `/api/audit/submit/` | 单条通过/打回 |
| POST | `/api/audit/bulk_submit/` | 批量审核 |

前端菜单、路由命名建议区分 **「审核台」** 与 **「安全审计」**，避免与 `/system/audit-log` 产品需求混为一谈。

### 8.3 系统模块实现策略（在接口未就绪前）

- **RBAC 页面**：占位 + Mock，或与后端确认是否通过 **Django Admin** 完成首版配置、前端仅文档化。
- **审计 Diff**：待后端提供「日志列表 + 单条详情（含 before/after）」契约后再对接；需求中的 Diff 展示组件可先独立开发，使用假数据。
