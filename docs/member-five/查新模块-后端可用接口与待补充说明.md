# 查新模块：后端可用接口与待补充说明

本文档依据仓库根目录《[后端接口说明文档.md](../../后端接口说明文档.md)》逐项梳理**查新服务模块**（见 [02-novelty-search.md](./02-novelty-search.md) 与其中 **§2.1～2.3 流程图**）可立即依赖的 HTTP/WebSocket 能力，以及**仍需后端补充契约**的部分。约定与全局响应形态以说明文档 **§1** 为准。

---

## 1. 结论摘要

| 类别 | 说明 |
|------|------|
| **可直接用于查新界面联调** | 单条「是否最新」、批量模糊查新、族谱树、标准联想搜索、标准分页列表与详情、企标文件异步解析入队、规范性引用入库、前言解析（与「国标」侧校对相关，非查新主链必选）等（见 §2）。 |
| **文档已说明但需确认运行环境** | 企标分析、Celery/Redis、WebSocket 等依赖部署与 worker 是否就绪。 |
| **查新产品主链缺口** | 独立「查新任务」CRUD、专用表持久化与确认、任务级比对进度、查新 PDF 生成与按任务下载、与流程图一一对应的归档检索等（见 §4）。 |

---

## 2. 现成可用接口（推荐在查新界面中的用途）

下列路径均以 `/api/` 为前缀（见说明文档）。**「查新界面落点」**对应 [02-novelty-search.md](./02-novelty-search.md) 中的页面与 Tab。

### 2.1 标准库侧：查新 / 溯源 / 检索（核心）

| 方法 | 路径 | 说明文档章节 | 作用简述 | 查新界面落点 |
|------|------|----------------|----------|----------------|
| GET | `/api/standards/check-latest/` | §2.3 | 单条标准是否现行最新、`pedigree_chain`、`current_latest_id` 等；成功体**无统一 `code` 包装** | **比对明细**逐行结论、侧栏摘要；与流程 **StatusMatch / 三态结论** 对齐 |
| POST | `/api/standards/batch-fuzzy-check/` | §2.9 | 批量关键字查新，返回每行 `isLatest` / `latestId` / `error` | **比对明细**批量刷新、专用表确认后一键跑批 |
| GET | `/api/get_tree_data/` | §2.19 | 族谱 `nodes` + `links` | **比对明细**行展开谱系图/关系列表；流程 **TraceLogic / FollowPedigree** 的展示数据源 |
| GET | `/api/standards/basic-search/` | §2.6（约） | Query `q`，标准号/名称联想 | **新建任务**、**专用表编辑**时录入与纠错 |
| GET | `/api/standards/` | §2.2 | 分页列表，`search`、`ex_state` 等 | 辅助「库内是否存在」人工核对、与列表联动（**非** Exists 的自动判定本身） |
| GET | `/api/standards/detail-info/` | §2.10 | 单条详情卡片（CCS/ICS、起草单位等） | 比对行展开**元数据补充** |
| GET | `/api/standards/download-doc/` | §2.11 | 按标准号下载库内 PDF | 若查新需核对原文（可选） |

### 2.2 企标解析与引用链（与流程 Upload / PDFParsing 相关）

| 方法 | 路径 | 说明文档章节 | 作用简述 | 查新界面落点 |
|------|------|----------------|----------|----------------|
| POST | `/api/analyze_qb_references_auto/` | §2.29 | `multipart` 上传企标 PDF/DOCX，**异步** Celery；成功表示入队 | **新建任务**上传企标 → **解析中**阶段入口 |
| POST | `/api/insert_anti_warn/` | §2.30 | JSON：`source_bz_id`、`references[]` 等，写入映射/预警链 | **专用表确认后**「写回引用链」类操作（若产品需要） |

### 2.3 前言差异（与查新主链弱相关，可选）

| 方法 | 路径 | 说明文档章节 | 作用简述 | 查新界面落点 |
|------|------|----------------|----------|----------------|
| GET | `/api/dify/preface-diff/` | §2.27 | 前言解析状态与结果 JSON | 若任务需与「国标前言」交叉核对，可挂在任务详情**扩展区** |
| POST | `/api/dify/preface-upload/` | §2.28 | 上传前言 PDF 并触发解析 | 同上，**非**查新主流程必选项 |

### 2.4 WebSocket（异步结果推送）

| 资源 | 说明文档章节 | 作用简述 | 查新界面落点 |
|------|----------------|----------|----------------|
| `ws://<host>/ws/dify_results/`（生产 `wss://`） | §4 | `message` 内 JSON，按 `type` 分支；文档已列 `compliance_eval`、`preface_highlights` 等 | **解析中 / 比对中**进度与结果推送的**候选通道**；**需在说明文档中补充**与「企标解析 / 查新任务」对应的 `type` 与载荷，前端才能稳定分支 |

### 2.5 与查新易混淆、不建议当作「查新 PDF」的接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET/POST | `/api/standards/export-report/` | 说明文档明确为**合规审查 Excel**，**不能**替代查新结论 PDF（见 §4.3）。 |

## 3. 弱相关或边界能力（按需接入）

- **`GET /api/standards/statistics/`**、大屏预警类等：更偏工作台/运营看板；查新列表页若要展示「全局统计」可选用，**非**单任务闭环必需。
- **`POST /api/standards/` 等 DRF CRUD**（说明文档 §3）：在「库内无数据 → 引导补录标准」时，若产品允许从查新页跳转标准库或调创建接口，需单独权限与产品设计；**文档未与查新任务绑定**。

## 4. 待补充接口（缺失项详细说明）

以下条目与 [后端未实现的接口信息汇总.md](./后端未实现的接口信息汇总.md) **§2 查新服务模块**一致，在此**展开用途、建议数据形态与流程对应**，便于评审与排期。

### 4.1 查新任务实体与生命周期

**缺失原因（现状）**：说明文档 HTTP 章节**无**独立「查新任务」资源；无法仅凭文档实现任务列表、详情、状态机、取消/重试。

**用途**：

- 将流程图 **Start → Upload → … → Archive → End** 映射为**可持久化**的业务对象（任务 ID、创建人、来源类型、当前阶段、失败原因等）。
- 支撑 `/novelty-search` 列表分页筛选、`/novelty-search/tasks/:taskId` 工作台顶部 **Steps** 与权限控制。

**建议补充契约（示例级，非最终实现）**：

- `POST /api/novelty-tasks/`：创建任务（ body：来源类型、企标文件 id 或标准号表单、可选元数据）；返回 `task_id`、初始状态。
- `GET /api/novelty-tasks/`：分页列表，Query：`status`、`q`、`created_by`、`page` 等。
- `GET /api/novelty-tasks/{id}/`：详情含当前阶段、时间线、错误栈摘要。
- `POST /api/novelty-tasks/{id}/cancel`、`POST /api/novelty-tasks/{id}/retry`（可选）：与产品「失败恢复」一致。

**流程对应**：Start、Upload、Archive、End 及任务级 **失败 / 重试**（见 [02-novelty-search.md §2.3](./02-novelty-search.md)）。

---

### 4.2 企标解析结果与「查新专用表」

**缺失原因（现状）**：`analyze_qb_references_auto` 仅描述**入队**；**无**专用表资源的 GET/PATCH/确认接口；WebSocket **未约定**查新解析完成后的 `type` 与载荷。

**用途**：

- 承载流程 **GenDraftTable → HumanAudit → ConfirmTable**：初稿行、编辑、保存草稿、**确认后解锁**进入 LoopStart。
- 前端专用表 Tab 需要稳定行 id、版本号、确认人确认时间（审计）。

**建议补充契约（示例级）**：

- `GET /api/novelty-tasks/{id}/reference-sheet/`：返回专用表行数组（引用号、名称、技术指标片段、行状态等）。
- `PATCH /api/novelty-tasks/{id}/reference-sheet/`：批量或增量保存草稿。
- `POST /api/novelty-tasks/{id}/reference-sheet/confirm`：确认进入比对；后端校验后推进状态机。

**与已有接口关系**：解析仍可由 **`POST /api/analyze_qb_references_auto/`** 触发；结果落库后由上述 GET 读出，避免前端只靠 WS 拼表。

**流程对应**：PDFParsing、GenDraftTable、HumanAudit、ConfirmTable。

---

### 4.3 比对流水线与任务级进度

**缺失原因（现状）**：`check-latest`、`batch-fuzzy-check` 为**单次调用**；文档未描述「任务下按专用表行批量跑、可查询进度百分比 / 当前行」的编排 API。

**用途**：

- 支撑 **LoopStart / QueryM1** 与 UI「已处理 n/N」、取消长任务、部分失败重试。
- 与流程图 **Exists / TraceLogic** 的结果写回「每行比对结果」存储。

**建议补充契约（示例级）**：

- `POST /api/novelty-tasks/{id}/compare/run`：启动或继续比对（后端按专用表行循环调用标准库逻辑）。
- `GET /api/novelty-tasks/{id}/compare/status`：返回阶段、进度、当前 `bz_id`、错误行列表。
- `GET /api/novelty-tasks/{id}/compare-rows/`：比对明细表分页（存在性、三态、替代号、备注等）。

**与已有接口关系**：编排层内部可调用现有 **`check-latest`**、**`get_tree_data`**、必要时 **`batch-fuzzy-check`**；前端优先消费 **compare-rows** 聚合结果，减少 N 次浏览器直连。

**流程对应**：LoopStart、QueryM1、Exists、ManualHandle、TraceLogic、StatusMatch、三 Result、DataCompile、UIRender。

---

### 4.4 查新结论 PDF 与历史归档检索

**缺失原因（现状）**：说明文档**无**查新 PDF 专用生成/下载路径；**export-report** 为合规 Excel，不可替代。

**用途**：

- 支撑流程 **ReportGen → PDFGen**：生成含谱系历史与结论的 PDF、预览、下载。
- 支撑 **Archive**：按任务 id、时间、企业等**再次下载**与列表检索。

**建议补充契约（示例级）**：

- `POST /api/novelty-tasks/{id}/report/pdf`：触发生成；异步则返回 job id 或任务状态变为「报告生成中」。
- `GET /api/novelty-tasks/{id}/report/pdf`：下载或 302 到对象存储 URL。
- 列表接口扩展字段：`has_report`、`report_generated_at` 等。

**流程对应**：ReportGen、PDFGen、Archive；及 §2.3「跳过 PDF 仍归档」时 `has_report=false`。

---

### 4.5 WebSocket 消息类型（查新专用）

**缺失原因（现状）**：§4 仅列 `compliance_eval`、`preface_highlights` 等，**未列**企标解析完成、专用表就绪、比对进度、报告生成完成等。

**用途**：满足需求文档中**长耗时异步须有可见反馈**；减少轮询压力。

**建议补充**：在说明文档 §4 增加查新相关 `type` 枚举与每种载荷 JSON Schema（或与 `task_id` 的关联字段）。
