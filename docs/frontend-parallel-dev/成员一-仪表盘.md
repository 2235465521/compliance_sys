# 成员一：仪表盘模块开发约定

本文约定**成员一**在并行开发中的职责边界、代码与资源放置位置，以及 Git 合并与自测要求。全组通用规则见同目录 [README.md](./README.md)。

---

## 1. 负责范围与路由

| 项目 | 说明 |
|------|------|
| **路由 path** | `/dashboard` |
| **页面入口** | `frontend/src/pages/dashboard/index.tsx` |
| **侧栏菜单** | 名称「仪表盘」，已在 `frontend/src/routes/menu.tsx` 中配置；若仅调整本模块文案或图标，改动时避免影响其他菜单项 |

**职责概要**：工作台级数据概览（待办、统计、图表等），对应需求文档中「仪表盘模块」下的各类卡片与图表。**不包含**其他业务模块的页面实现。

---

## 2. 代码目录与文件命名

以 `frontend/src/pages/dashboard/` 为唯一业务根目录：

| 类型 | 放置位置 | 说明 |
|------|----------|------|
| 页面入口 | `pages/dashboard/index.tsx` | 默认导出页面组件，供路由引用 |
| 模块内组件 | `pages/dashboard/components/` | 仅仪表盘使用的区块，如 `TodoCard.tsx`、`StatOverview.tsx` |
| 模块 hooks | `pages/dashboard/hooks/` | 如 `useDashboardStats.ts` |
| 工具函数 | `pages/dashboard/utils/` | 如图表数据格式化 |
| 静态资源 | `pages/dashboard/assets/` | 本页插图、仅仪表盘使用的图标文件等 |
| 接口封装 | `frontend/src/services/dashboard.ts` | 与后端约定的仪表盘相关 API |
| 状态 | `frontend/src/stores/dashboard.ts` | 若需跨子组件共享筛选条件、时间范围等 |
| 类型定义 | `frontend/src/types/dashboard.ts` | 请求/响应 DTO、图表数据结构 |

若需**跨模块复用**的通用组件（例如全站通用的 KPI 卡片），新建在 `frontend/src/components/`，命名需清晰（如 `components/StatCard/`），并在 Pull Request 中说明给哪些模块使用。

---

## 3. Ant Design / ProComponents 使用边界

- 列表、表单优先使用 **ProTable、ProForm** 等 ProComponents，与全站风格一致；避免再包一层无意义的「业务外壳」除非确有复用价值。
- 图表：若引入 **@ant-design/charts** 或 **ECharts** 等，须在 PR 中说明选型原因，并统一由一人维护版本，避免重复引入两套图表库。
- 仪表盘多为只读展示，注意大数据量时的性能（分页、按需请求、避免一次性渲染过多图表实例）。

---

## 4. 接口与 Mock

- 基地址：通过环境变量 `VITE_API_BASE_URL`（见 `frontend/.env.example`），请求经 `frontend/src/services/request.ts` 发出的实例。
- 仪表盘接口统一写在 `services/dashboard.ts` 中，**不要**在 `index.tsx` 内散落裸 `fetch`/`axios`。
- 若后端未就绪，可在 `services/dashboard.ts` 内用临时 Mock 数据并加注释 `// TODO: 替换为真实接口`，或单独 `services/dashboard.mock.ts` 仅在开发环境引入（与团队约定后执行）。

---

## 5. Git 分支、PR 与 Code Review

- **个人分支**：在 GitHub 上以主分支为基线创建**自己的功能分支**，仪表盘相关修改**全部在该分支上**完成后再发 PR 合入主分支；勿直接在主分支上开发。完整流程见 [README.md - GitHub 分支与合并流程](./README.md#github-分支与合并流程)。
- **分支命名**：`feature/dashboard-<简述>`，例如 `feature/dashboard-todo-cards`。
- **涉及共享文件时**：若需修改 `frontend/src/routes/index.tsx` 或 `menu.tsx`（例如新增子路由 `/dashboard/xxx`），合并前先拉取主分支；PR 描述中写清「仅仪表盘相关」。
- **勿修改**其他成员目录下的 `pages/<其他模块>/`，除非评审通过的小范围共用改动。

---

## 6. 自测清单

合并或提交 PR 前在 `frontend` 目录执行：

- [ ] `npm run build` 无报错。
- [ ] 本地 `npm run dev` 进入 `/dashboard` 页面无控制台报错（与本次改动相关）。
- [ ] 若新增路由子路径，确认 `routes/index.tsx` 中父子路由完整、侧栏高亮正常。
- [ ] 若新增 npm 依赖，已在 PR 中说明用途。

---

## 7. 与其他成员的协作点

- 仪表盘上「跳转至某业务模块」的链接，使用 **React Router** 的 `<Link>` 或 `useNavigate`，路径与 [README.md](./README.md) 中的路由表保持一致，勿写死未约定路径。
- 若需读取全局用户信息或权限，优先与全组约定是否放在 `stores/auth.ts` 或后续 `stores/user.ts`，避免在仪表盘内重复造轮子。
