# 成员四：预警系统模块开发约定

本文约定**成员四**在并行开发中的职责边界、代码与资源放置位置，以及 Git 合并与自测要求。全组通用规则见同目录 [README.md](./README.md)。

---

## 1. 负责范围与路由

| 项目 | 说明 |
|------|------|
| **路由 path** | `/alert` |
| **页面入口** | `frontend/src/pages/alert/index.tsx` |
| **侧栏菜单** | 「预警系统」，配置在 `frontend/src/routes/menu.tsx` |

**职责概要**：预警列表、预警看板、通知类展示，以及与「一企一库」监控相关的前端呈现（数据以后端为准）。需求文档中涉及**正向激励/负向预警**、预警通知单等，前端负责列表/详情/状态筛选与**实时或准实时更新**的交互占位（轮询间隔、后续 SSE/WebSocket 与后端约定）。

---

## 2. 代码目录与文件命名

以 `frontend/src/pages/alert/` 为业务根目录：

| 类型 | 放置位置 | 说明 |
|------|----------|------|
| 页面入口 | `pages/alert/index.tsx` | 总览或列表入口；若有详情子页，可扩展 `pages/alert/detail/index.tsx` 并在路由中注册 |
| 组件 | `pages/alert/components/` | 如 `AlertCard.tsx`、`AlertFilters.tsx`、`RiskBoard.tsx` |
| hooks | `pages/alert/hooks/` | 如 `useAlertList.ts`、`useAlertPolling.ts`（轮询须处理卸载清理） |
| 工具 | `pages/alert/utils/` | 预警级别映射、时间展示等 |
| 静态资源 | `pages/alert/assets/` | 本模块专用图标、空状态插图 |
| 接口 | `frontend/src/services/alert.ts` | 列表、详情、确认已读等 |
| 状态 | `frontend/src/stores/alert.ts` | 如未读数量、筛选条件（与仪表盘跳转联动时保持字段一致） |
| 类型 | `frontend/src/types/alert.ts` | 预警单 DTO、分页结构 |

跨模块复用的「通用列表/徽章」类组件可放在 `frontend/src/components/`，避免与业务强耦合命名（如 `components/BadgeCount`）。

---

## 3. Ant Design / ProComponents 使用边界

- 列表与详情优先 **ProTable、Descriptions、Tag** 等，保持与全站后台风格一致。
- **轮询**：使用 `setInterval` 或 `requestAnimationFrame` 等时，必须在 `useEffect` 清理函数中清除；后续若改为 WebSocket，将连接逻辑集中在 `hooks/` 或 `services/alert.ts`。
- 大屏/看板若需图表，与成员一（仪表盘）协调**同一套图表库**，避免重复引入。

---

## 4. 接口与 Mock

- 请求统一走 `services/request.ts`，封装在 `services/alert.ts`。
- 分页、排序参数与后端约定后固定类型，写在 `types/alert.ts`。
- Mock 数据可临时写在 service 内并标注 `TODO`，便于联调替换。

---

## 5. Git 分支、PR 与 Code Review

- **个人分支**：在 GitHub 上以主分支为基线创建**自己的功能分支**，预警模块相关修改**全部在该分支上**完成后再发 PR 合入主分支；勿直接在主分支上开发。完整流程见 [README.md - GitHub 分支与合并流程](./README.md#github-分支与合并流程)。
- **分支命名**：`feature/alert-<简述>`，例如 `feature/alert-list-filters`。
- **共享文件**：改动 `routes/index.tsx`、`menu.tsx` 时遵循「只增不改他人行；合并前拉主分支」。
- PR 描述中若涉及「仪表盘待办数字与预警联动」，说明字段依赖，便于成员一 Code Review。

---

## 6. 自测清单

- [ ] `npm run build` 通过。
- [ ] `/alert` 页面可访问，无与本次改动相关的控制台错误。
- [ ] 若实现轮询，离开页面后网络面板无持续请求（或已按产品要求保留）。
- [ ] 新增依赖已说明。

---

## 7. 与其他成员的协作点

- **成员一（仪表盘）**：若「预警看板」与仪表盘跳转互通，约定 query 参数（如 `?enterpriseId=`）或路由路径，并在双方文档或 README 中补一句链接约定。
- **成员五（企业档案）**：一企一库档案入口与预警对象关联时，字段命名与 `types/enterprise-archive.ts`（或后端契约）对齐，避免重复定义冲突。
