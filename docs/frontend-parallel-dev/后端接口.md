# 标准管理系统 - 核心后端接口文档 (Django)

本文档基于系统当前的后端真实代码实现（包含 `api/urls.py`、`api/views.py`、`api/views_dify.py`、`api/views_duplicate.py` 等），汇总了所有核心业务流的后端接口细节。

## 1. 基础标准查询与控制层 (基于 DRF ModelViewSet)

后端针对核心数据表在 `urls.py` 中使用了 `DefaultRouter` 生成标准的 RESTful API。基础前缀为 `/api/`。

### 1.1 DRF 自动绑定对象与基础路径
以下路径全面支持标准的 `GET` (列表/分页/过滤)`、POST` (新增)、`PUT/PATCH` (修改)、`DELETE` (删除) 等请求：
* **`/api/standards/`**：调用 `StdBaseViewSet`，管理标准基础信息表。
* **`/api/detail_info/`**：调用 `DetailInfoViewSet`，管理包含起草归口单位的标准详表。
* **`/api/replaces_table/`**：调用 `ReplaceTableViewSet`，管理标准部分/全部更替演进史。
* **`/api/indexes_table/`**：调用 `IndexTableViewSet`，管理系统AI抽取的指标数据库。
* **`/api/warnings/`**：调用 `WarningViewSet`，管理预警库信息（注：非常驻业务）。
* **`/api/statistics/`**：调用 `StatisticalViewSet`，管控统计表访问量及引次。
* **`/api/relations/`**：调用 `StandardRelationViewSet`，专供 ECharts 图表，控制血脉继承关系。

### 1.2 `standards` 自定义高阶行为接口
这部分由 `api/views.py` 中的 `@action` 提供。

#### 查询判定标准最新演进状态
* **URL**: `/api/standards/check-latest/`
* **Method**: `GET`
* **Query 参数**: `bz_id` (目标标准号)
* **业务行为**: 基于谱系逻辑，顺着演进链条向后推查，返回当前查询标准号的最新现行版是谁，以及它的溯源链文字。

#### 导出带颜色的审查 Excel (合规性报告)
* **URL**: `/api/standards/export-report/`
* **Method**: `GET` 或 `POST`
* **参数**:
  * GET 传入 `bz_id` 导出一条。
  * POST 传入 JSON `{"bz_ids": ["GB 1", "GB 2"]}` 支持前端勾选后的批量批量导出。
* **业务行为**: 将标准的基础信息和相关的谱系替换信息拉平后写入本地生成的 Excel 数据流并返回下载响应。

#### 工作台：基本模糊搜索
* **URL**: `/api/standards/basic-search/`
* **Method**: `GET`
* **Query 参数**: `q` (搜索关键字)
* **业务行为**: 使用 Django `Q()` 支持标准号和标准名的多源 LIKE 查询匹配，按日期倒序最多送出一百条，以支撑低延迟的模糊输入框及下拉列表。

#### 工作台：大屏统计汇总数据
* **URL**: `/api/standards/statistics/`
* **Method**: `GET`
* **业务行为**: 扫掠 `StdBase` 全表按前缀 (GB/QB/DB 等) 以及执行状态分门别类算总数提供给 ECharts 图表渲染。

#### 级联依赖（被动）预警分析
* **URL**: `/api/standards/warning-trace/`
* **Method**: `GET`
* **Query 参数**: `bz_id` (受检标准号)
* **业务行为**: 分析演进链。如果该款国家标准已经不是最新版本，就去 `AntiWarnChain` 反向牵连数据库中找出目前还在引用它、受牵连的其它所有地方企业标准进行前端报备。

#### 批量模糊与族谱逆推引擎查询
* **URL**: `/api/standards/batch-fuzzy-check/`
* **Method**: `POST`
* **Body 参数**: `{"keywords": ["匹配词1", "匹配词2"]}`
* **业务行为**: 这个主要是原生 SQL，循环词组检索。在查到结果若是“废止”，将直接启动无限循环查找其 `new_bz_id` 或下一代谱系，向前端展示最新可用的更替者和是否是真最新的真假检验。

#### 取回标准卡片详情补充数据
* **URL**: `/api/standards/detail-info/`
* **Method**: `GET`
* **Query 参数**: `bz_id`
* **业务行为**: 用于弹窗或抽屉调取当前选定标准的完整起草单位与分类序列。

#### 下载 PDF 落地物理文件
* **URL**: `/api/standards/download-doc/`
* **Method**: `GET`
* **Query 参数**: `bz_id`
* **业务行为**: 使用终极去噪策略，清洗 `bz_id`，去挂载卷的核心磁盘 `/app/docs` (部分代码指向 Z盘) 匹配 PDF 文件并封装下载流给前端。

#### 工作台实时告警面板兼红灯流转
* **URL**: `/api/standards/dashboard-alerts/`
* **Method**: `GET`
* **业务行为**: (心跳接口) 每天计算判断 `即将实施` 的标准是不是到了实施期。到了则执行：当前升“现行”，同时寻找其旧日的老标准强制打入“废止”。并在返回前 30 天需要提醒的废除及即将实施内容给右侧组件面板。

## 2. 预警和拓扑关系独立接口 (views.py)

#### 获取标准血脉图关系结构
* **URL**: `/api/get_tree_data/`
* **Method**: `GET`
* **Query 参数**: `bz_id`
* **业务行为**: 取当前标准同族的 `tree_id`，然后去 `StandardRelation` 及 `StdBase` 一键抽拔全部节点与父级到子级的代替线段。

#### 后台心跳自巡检：生产品台报警
* **URL**: `/api/warnings/scan`
* **Method**: `POST` / `GET`
* **业务行为**: 主动执行全局 SQL，寻找“两个版本(新的和老的)的状态都是现行或即将实施”的老赖逻辑错误，强行更变其状态并在 `realtime_warnings` 生成给管理看的强制性弹框提示。

#### 拿回提示单与一键已读
* **URL**: `/api/warnings/list` 或 `/api/warnings/mark_read`
* **Method**: 上为 GET, 下为 POST (附 id)
* **业务行为**: 提供给顶部的红色铃铛读取数据与清除未读提醒功能。

## 3. Dify 大模型与 AI 审查深度集成核心接口 (views_dify.py)

#### 企标文件入场与全自动 AI 排查触发机制
* **URL**: `/api/analyze_qb_references_auto/`
* **Method**: `POST` `[multipart/form-data]` 带有 `file`
* **业务行为**: 将被解析文件的副本传入跨容器的共享路径 `/app/shared_temp` 中。随即将异步指令发送至 Celery 的 `process_qb_dify_task` ，迅速结束连接保证前端不阻塞。之后一切由 Celery 对接 Dify，并将最终解析与碰撞比对由 WebSocket `dify_notifications` 发给页面。

#### 解析企标引用录入映射及建立预警联防反向链
* **URL**: `/api/insert_anti_warn/`
* **Method**: `POST`
* **Body 参数**: 大模型吐回的解析 JSON 报文
* **业务行为**: 处理企标所有的引用的引用关系，填入 `qb_mapping_newgb` 和 `anti_warn_chain`。对于没给年代号的历史文件，系统会有个推演算法计算当时时间前的最终版本。更新反向追踪以及增加 `statistical` 表的引次。

#### 单标准全参数指标数据池剥取
* **URL**: `/api/insert_indexes/`
* **Method**: `POST`
* **业务行为**: 后置防爆脱壳模块。处理大模型提取的一篇标准的各类分类要求，自动拨茧后把这些参数逐条插入 `index_table`，并且设置初始等待审核状态为 status=0。

#### [指标审核工作流模块]
* ** `/api/audit/pending_indexes/` (GET)**: 读取目前处于暂缓审核(status=0)的待办工作库交给审查人员。
* ** `/api/audit/submit/` (POST)**: 给指定指标给出裁决 (参数传入 `id`、`action: approve/reject` 与如被修篡后的详情内容)，完成录入并将入库状态翻盖。
* ** `/api/audit/bulk_submit/` (POST)**: 包含修篡预覆盖与根据勾选的 `ids` 列表全部“一刀切”过审业务的双端聚合接口。

#### 人工复写补绑规范性关系
* **URL**: `/api/mapping/save/`
* **Method**: `POST`
* **Body 参数**: `{"enterprise_bz_id": "", "national_bz_id": ""}`
* **业务行为**: 如果系统遗漏或手动要指定企业标准到某某国家规范的标准关联关系就通过这里补强到 `qb_mapping_newgb` 数据库内部进行备案。

#### 前言修订差异解析及启动机制
* **URL**: `/api/dify/preface-diff/`
* **Method**: `GET`
* **Query 参数**: `bz_id`
* **业务行为**: 根据提供的 `bz_id`，查询 `StdRevisionDiff` 表缓存，查到秒返回。否则去 `/app/word_docs/` 里扫全盘找带有这个名称前缀的无水印 Word。若有文件则叫醒 Celery `extract_preface_diff_task` 分析并将处理信号扔到前台让其等待；若文件无就要求“上抛”。

#### 手动抛砖引玉：前言提取之自主兜底方案
* **URL**: `/api/dify/preface-upload/`
* **Method**: `POST` (带有 `bz_id` 和被传的 `file`)
* **业务行为**: 使用者提供无水印的文字版或原厂版文档后，将其保存至 `word_docs` 下并由系统召唤 Celery 直接接手进行大语言模型的“流式”(Streaming Server-Sent Event) 对接任务。

## 4. 防标准沉冗：新设标准智能语义重合过滤引擎 (views_duplicate.py)

#### 立功第一层 - 海选快打系统 (“字面形近字过滤引擎”)
* **URL**: `/api/duplicate/name-check/`
* **Method**: `POST`
* **Body 参数**: `{"keyword": "GB 或名字片段"}`
* **业务行为**: 在 `std_base` 库利用万向模糊检索找到池子后，使用机器本地计算 `SequenceMatcher` 判断比率，丢弃极少数（匹配不达 40%），并在包含关系的保底满分策略下向列表吐出最多前 50 条匹配最准的数据。

#### 立功第二层 - 核心降维打击 (“语义超维向量拦截网”)
* **URL**: `/api/duplicate/semantic-check/`
* **Method**: `POST`
* **Body 参数**: `{"intent_text": "想立项一个电池回收的新材料标准..", "candidate_ids": ["可疑范围的id串1", ...]}`
* **业务行为**: 主发信号将以上内容喂养到 Celery 管道的任务 `run_semantic_check_task` 中。
* **Celery 流程**:
  1. 调用系统常驻环境内的机器深度模型 `paraphrase-multilingual-MiniLM-L12-v2`，将自然语言意图转换为 384 纬度数学空间计算变量。
  2. 求余弦相似度测距：遍历取出涉事标准的 `StdScope` 内容数据库，与其已入库转换出的范围向量对比算出重合率。
  3. 重合率极高的情况将调用 Dify API 使用裁判员的大规模长文本生成其深度“拒收/驳回报文”。
  4. 使用 `channels`/`WebSocket` 技术通过名为 `dify_notifications` 的房间把红脸或绿灯的宣判书抛掷前台。
