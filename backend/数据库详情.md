# STSC_standard_database — 数据库详情（按表）

> **版本**：建库阶段定稿（2026-06）  
> **库名**：`STSC_standard_database`  
> **相关**：[分层规范.md](./分层规范.md) · [维护手册.md](./维护手册.md) · [README.md](./README.md)

本文按 **逻辑分层 + 业务模块** 说明 STSC 中每一张表（及核心视图）的用途、字段要点、关联关系与读写方。行数为 **本机 STSC 实测**（2026-06），随 ETL/业务会变化。

## 0. 阅读说明

### 0.1 分层与标签

| 层级 | 前缀/表族 | 写入方 | 主要读者 |
|------|-----------|--------|----------|
| **L0** | `users`、`auth_*`、`django_*`、`regulation_auth_*` | 各 Django 应用 | searpage / regulation |
| **L1** | `std_*`、字典、单位、地区 | **标准导入 ETL** | searpage、regulation（只读） |
| **L2** | `std_scope_table`、`std_statistical` | ETL / 批任务 | 查重、统计 |
| **L3** | `regulation_*` | **regulation 应用** | 合规、查新、预警 |

### 0.2 两把「标准号」键（勿混）

| 键 | 所在层 | 含义 | 示例 |
|----|--------|------|------|
| **`std_base.std_id`** | L1 catalog | 全库标准事实唯一号 | `GB/T 1.1-2020` |
| **`(catalog_std_type_no, subject_code)`** | L3 regulation | 被评价/监控主体 | `(NULL, Q/AHYY 001-2020)` 企标；`(00, GB/T 191-2008)` 国标主体 |

企标 **Q/** 一般 **不在 catalog**，故 regulation 侧 `catalog_std_type_no = NULL`。

### 0.3 v1 旧表对照（STSC 中不存在）

| 旧表（standards_db_v1.0） | STSC 替代 |
|---------------------------|-----------|
| `national_standard_basic` | `std_base` + `std_gb_detail` 等 |
| `enterprise_standard_basic` | `regulation_evaluated_standard_basic` |
| `enterprise_standard_reference_mapping` | `regulation_normative_reference_mapping` |
| `standard_pedigree` | `std_pedigree` + `std_ped_chain` |

## 1. L0 — 框架与用户（11 张基表 + 4 Django 系统表）

### 1.1 `users` · 约 4 行 · `[searpage]`

| 项 | 说明 |
|----|------|
| **业务** | 检索平台（std_searpage_v2）登录账号；自定义 User，**非** Django 默认 `auth_user` |
| **读** | searpage 认证、用户管理 API |
| **写** | searpage 管理员 |
| **主键** | `id` |
| **核心字段** | `username`、`password`；扩展 `age`、`status`、`gmt_create` / `gmt_modified` |
| **关联** | `users_groups` → `auth_group`；`users_user_permissions` → `auth_permission` |
| **备注** | 从 mydate 复制，**表名不改**；与 `regulation_auth_user` 隔离 |

### 1.2 `users_groups` · `[searpage]`

用户与 Django 组的 M2M。字段：`user_id` → `users`，`group_id` → `auth_group`。

### 1.3 `users_user_permissions` · `[searpage]`

用户直接绑定的权限（绕过组）。`user_id` + `permission_id`。

### 1.4 `auth_group` / `auth_group_permissions` / `auth_permission` · `[searpage]`

searpage 侧 Django 权限模型。`auth_permission.content_type_id` → `django_content_type`（shared）。

### 1.5 `regulation_auth_user` · 0 行 · `[regulation]`

| 项 | 说明 |
|----|------|
| **业务** | 合规/查新/预警平台 Django 用户（切 STSC 后使用） |
| **结构** | 与 Django `auth_user` 同构：`username`、`password`、`is_staff` 等 |
| **数据** | 由 `05_etl_v1_auth.sql` 从 v1 迁入；本机 v1 无用户故为空 |

### 1.6 `regulation_auth_group` / `regulation_auth_permission` / M2M 表 · `[regulation]`

regulation 独立权限体系，表名带 `regulation_auth_` 前缀，避免与 searpage `auth_*` 冲突。权限定义约 **68** 条（从 v1 复制）。

### 1.7 `django_content_type` · 27 行 · `[shared]`

Django 内容类型注册表。两项目若共库，**共用**此表。

### 1.8 `django_migrations` · 19 行 · `[shared]`

Django 迁移历史（当前主要为 searpage `standard_app` 等）。regulation 切库后 migrate 会 **追加** 记录，勿删他项目条目。

### 1.9 `django_session` / `django_admin_log` · `[shared]`

会话与 Admin 操作日志；按项目配置区分使用。

## 2. L1 — 标准 catalog（标准事实）

> **权威来源**：mydate 全量复制 + ETL 增量。  
> **子表统一**：`base_id` → `std_base.id`（13-1 已建 FK，DELETE CASCADE）。

### 2.1 `std_base` · 约 470,524 行

| 项 | 说明 |
|----|------|
| **业务** | **全类型标准主表**：国标、行标、地标、团标、ISO、IEC 等一切的「身份证」 |
| **读** | searpage 检索/详情/分析；regulation 查新/引用解析/谱系（目标态） |
| **写** | **仅**标准导入脚本 |
| **UK** | `std_id`（标准号字符串） |
| **核心字段** | `std_type`（文本类型）、`std_type_no`（00～05 等）、`std_chinesename` / `std_englishname`、`release_date` / `implement_date` / `abolish_date`、`std_status`、`ex_state`（0 废止 / 1 现行 / 2 即将实施） |
| **关联** | 几乎所有 `std_*` 子表、`view_std_full`、中层 `std_scope_table.std_id` |
| **对应 v1** | 替代 `national_standard_basic.std_code` → 此处为 **`std_id`** |

### 2.2 分类型明细表（1:1 `base_id`）

每类标准扩展字段不同；与 `std_base` **一行标准一行 detail**。

| 表 | 约行数 | 类型 | 业务要点 |
|----|--------|------|----------|
| **`std_gb_detail`** | 77,981 | 国标 GB/GB/T | ICS/CCS、起草人、归口/副归口、主管部门、采标情况等 |
| **`std_hb_detail`** | 118,237 | 行标 | 含 `record_no`、行业类型、技术委员会、批准部门等 |
| **`std_db_detail`** | 110,093 | 地标 | 类似行标 + `suggest_dept` 等 |
| **`std_tb_detail`** | 78,399 | 团标 | 含 `scope`、`main_tech_cont`、团体、专利标记、业务范畴等 |
| **`std_iso_detail`** | 51,077 | ISO | ISO 专用扩展 |
| **`std_iec_detail`** | 18,456 | IEC | IEC 专用扩展 |

**UK**：各表 `base_id` 唯一。  
**读路径**：searpage `view_std_full` 宽表 JOIN；regulation 按 `std_type_no` 选 detail 表。

### 2.3 `std_extend_h` · 约 265,295 行

| 项 | 说明 |
|----|------|
| **业务** | 起草单位 **横向摘要**（`draft_unit` 长文本，多单位逗号/顿号拼接） |
| **用途** | 检索展示、起草单位统计的文本兜底 |
| **FK** | `base_id` → `std_base` |

### 2.4 `std_extend_s` · 0 行

起草单位 **竖向结构化**扩展（与 `_h` 相对）；当前库无数据，结构保留。

### 2.5 `std_pedigree` · 约 85,891 行

| 项 | 说明 |
|----|------|
| **业务** | 标准 **谱系关系**：某年代版标准对应的 **现行最新号**、谱系 ID |
| **读** | 查新（是否被新标准代替）、合规 Step3 引用解析 |
| **核心字段** | `base_id`；`std_id_latest`（现行版标准号）；`ped_id`（谱系链 ID） |
| **对应 v1** | 替代 `standard_pedigree.latest_std_code`；链文本在 `std_ped_chain` |
| **备注** | 同一 `std_id` 可有多行（多谱系），与 v1「一行一链 part_chain」结构不同 |

### 2.6 `std_ped_chain` · 约 59,018 行

| 项 | 说明 |
|----|------|
| **业务** | 按 `ped_id` 存储 **谱系链 JSON**（替代/被替代关系树） |
| **关联** | `ped_id` 对齐 `std_pedigree.ped_id`（**无 FK**，靠 ETL 一致） |
| **读** | searpage 谱系演进树；regulation 查新链解析（需适配 JSON） |

### 2.7 `std_replace` · 约 77,493 行

| 项 | 说明 |
|----|------|
| **业务** | 标准 **代替关系** 事实表（被谁代替、代替类型） |
| **字段** | `base_id`；`replace_id`；`replace_std_name`；`replace_type` |
| **用途** | 辅助查新；主路径仍优先 `std_pedigree.std_id_latest` |

### 2.8 `std_filepath` · 约 716,124 行

| 项 | 说明 |

| **读** | 标准详情下载、Dify 抽指标/引用时的文件源 |
| **优先级** | regulation 侧 **`regulation_standard_file_override` 优先**，再 fallback 本表 |
| **FK** | `base_id` → `std_base` |

### 2.9 `std_index` · 0 行
