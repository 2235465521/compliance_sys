# DDL / ORM 对齐：职责与流程

本文件配合 [《后端模块开发分工清单》](./backend-模块开发分工清单.md) 文末「DDL / ORM 对齐职责」一节使用。

## 目标

- [`v1.0-sql/`](../v1.0-sql/) 中的表结构、索引与约束与 Django **models + migrations** 一致或可追溯映射；当前落地数据库为 **MySQL 8.x**，DDL 方言以团队选型为准。
- 避免多人并行开发时出现「手写 SQL 与 ORM 两套真相」。

## 建议角色

| 角色 | 职责 |
|------|------|
| **数据负责人（可兼任架构）** | 评审一切涉及 `v1.0-sql` 或 `models.py` / `migrations/` 的变更；维护「表 ↔ App」对照备注。 |
| **模块开发** | 在本模块 `models` 变更前提交草稿或与数据负责人对齐；不在 router 内长期保留裸 SQL。 |

## 评审触发条件（任一即需要 Review）

- 新增或修改 `v1.0-sql/*.sql`。
- 新增或修改某个 `apps/*/models.py` 且影响已有表。
- 新增 migration 含 `RunSQL`、外键、唯一约束变更。

## 文档维护

- 重大对齐结论可在 PR 描述中简述；复杂映射可追加一节到本文档或分工清单。
